# ImapFlow transport validation — Phase 1

Date: 2026-10-12 (Europe/Warsaw). Base: `design/imap-sync-engine`, `7ccabcad5390439e9ce906d1e9a9c196ffa04912`. Experiment branch: `experiment/imap-transport-validation`.

**Decision: feasible for further design work, with transport bounds and content validation still requiring adaptation. Not validated for production implementation or Phase 2.** Short completed SEARCH/FETCH commands can yield a reusable connection. Iteration batches, socket inactivity timeouts and parser defaults do not supply the complete proposed operation contract.

The working tree was clean before branch creation. Only this disposable harness and these two reports were added. Production sources, architecture/validation documents, Thunderbird research, dependencies and migrations were left unchanged. No accounts, databases, PRs, merges or pushes were used. The 50,000 + 10 benchmark was not started.

## Environment and reproduction

Actual versions and dependency source SHA-256 hashes are recorded in [measurements.json](../../../experiments/imap-transport/measurements.json). Installed ImapFlow is **2.0.6**, with the repository's existing conditional STORE patch; that patch does not change SEARCH/FETCH/IDLE/parsing. The ESM entry used by each child is recorded as `observations.runtimeEntry`. Existing Node 24.21.0, pnpm 12.7.0 and tsx 4.23.15 were used. No experiment dependency was added or upgraded.

The peer is a scripted loopback TLS IMAP4rev1 server, advertising IDLE, with synthetic PREAUTH, SELECT identity and actual command tags, untagged replies, literal byte counts and partial origins. All experiments use the real installed ImapFlow compiler, parser and transport. No ImapFlow method was mocked or replaced. Read-only internal socket/lock/parser observations supplement public API events.

## Assessment matrix

PASS below applies only to the stated transport proposition; it does not imply that untested production persistence is safe. UNCERTAIN indicates partial validation or an unresolved boundary. Expected unsafe outcomes can pass a harness assertion while failing a safety gate.

| Experiment                      | Assessment             | Evidence and boundary                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1 — Bounded SEARCH             | UNCERTAIN              | Compliant closed numeric intervals return independently; all results are buffered. Numeric span bounds compliant UID cardinality, not hostile responses, aggregate wire bytes, server cost or memory independently of parser configuration.                                                                                                                         |
| E2 — Bounded FETCH / real yield | PASS                   | Exhaustion after tagged completion and explicit lock release permits reuse. First row, generator return, server completion and lock release are separate events; early return does not cancel the command.                                                                                                                                                          |
| E3 — Slow/hanging/cancel        | UNCERTAIN              | Network hangs, trickle, stalled literals, SELECT and DONE are terminated by destructive close, including a real 10-second deadline. An in-process timer is delayed by synchronous CPU work; no unconditional wall-clock SLA is proven.                                                                                                                              |
| E4 — Late data / callbacks      | PASS, controlled fence | Closed native socket and buffered iterator rows do not contaminate a fresh client; an explicit per-turn token rejects a delayed application callback. Library close cannot revoke already returned data or application callbacks; actual DB fencing remains NOT RUN.                                                                                                |
| E5 — Metadata limits            | FAIL                   | Configured literal/line/single-response limits work before complete parsing. Defaults allow a 1 MiB header, many sub-cap responses exceed the 2 MiB operation budget, and excessive nesting can be discarded before a successful empty FETCH result. Proposed complete byte/evidence contract is not provided by defaults or application checks.                    |
| E6 — Partial content            | UNCERTAIN              | Correct offsets, 7-byte boundary splits and 256 KiB slices reconstruct raw/decoded content with a persistent decoder and permit intervening NOOP. Disconnect remains incomplete. Oversize and wrong-origin replies are accepted by raw fetch; origin is not exposed in the returned body-parts map. Hostile-peer safety and restartable decoding remain unresolved. |
| E7 — Mailbox lock / ownership   | PASS                   | Explicit holder owns lock across commands, competing lock acquisition waits, normal error retains lock, destructive close clears/rejects locks. Lock-free commands can still run; one account owner remains necessary.                                                                                                                                              |

| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `search-small`, `search-large`               | `UID SEARCH UID 1:128` versus `1:16384`, dense hits, complete untagged SEARCH line, tagged OK delayed 80 ms. Compare size, memory and settlement after completion. This is transport cardinality testing, not a mailbox ingestion benchmark.                                                                                                                       |
| `search-sparse`                              | Interval `1:1000000000`, only UIDs 1, 100000 and 1000000000. Numeric interval width alone does not predict returned data size. No sparse probing algorithm is implemented.                                                                                                                                                                                         |
| `search-out-of-range`                        | Request `1:128`, deliberately return 16,384 identities. | `search-multi-response`, `search-line-cap`   | 64 SEARCH replies of 256 hits accumulated by one command; configured per-response limits do not cap that accumulation. Separate 1 KiB line limit rejects the large single reply and SEARCH settles `false`.                                                                                                                                                        |
| `fetch-complete`, `fetch-incomplete`         | Three requested headers; emit three or omit UID 3, tagged OK delayed 80 ms. Rows arrive before tagged completion; exhausted iterator waits for completion. Omission is accepted as a successful two-row result. Lock stays held until explicit release; NOOP can run while that lock is held.                                                                      |
| `fetch-break`                                | Three rows already sent, tagged OK delayed 150 ms. | `fetch-paused`                               | Consumer pauses after first row. Send FETCH tagged OK while paused. NOOP remains blocked until iterator return releases consumer backpressure. | `hang-search`, `hang-fetch`, `mid-fetch`     | Never complete SEARCH/FETCH; or declare 4096-byte header and send only a prefix. | `slow-fetch`                                 | Declare 4096-byte header and send one byte every 25 ms. 100 ms socket inactivity timeout does not enforce total time; a 350 ms watchdog aborts the transport. Buffered partial-literal bytes at abort are recorded.                                                                                                                                                |
| `disconnect-fetch`, `inactivity-fetch`       | Emit one header and drop after 30 ms, or send no FETCH data with 100 ms inactivity timeout. | `trickle-search`, `trickle-absolute-10s`     | Untagged OK every 25 ms without tagged completion. 100 ms socket inactivity timeout stays alive. Destructive deadlines of 350 ms and 10,000 ms settle `false` and close both endpoints.                                                                                                                                                                            |
| `reselect-hang`                              | New mailbox SELECT never replies; total watchdog includes preparatory LIST/LSUB and reselect, with no deadline reset.                                                                                                                                                                                                                                              |
| `event-loop-starvation`                      | Deliberately block the shared JavaScript event loop for 180 ms after arming a 50 ms timer. Observe watchdog lateness; network command may not yet have reached the server. This is a timer counterexample, not server latency.                                                                                                                                     |
| `idle-delayed-done`, `idle-hang-done`        | Real IDLE continuation, queued NOOP forces DONE; delay tagged IDLE OK by 150 ms or never complete. NOOP is sent only after completion; stuck DONE is closed at 220 ms.                                                                                                                                                                                             |
| `idle-disconnect`, `done-disconnect`         | Server closes during established IDLE or on receiving DONE. Both terminate and permit fresh-client work.                                                                                                                                                                                                                                                           |
| `late-network`                               | Abort SEARCH at 80 ms, new client gets UID 9, peer attempts obsolete response UID 777 at 220 ms. The closed socket rejects that write. Actual post-close delivery cannot be forced on the same TCP connection.                                                                                                                                                     |
| `buffered-after-close`                       | Three FETCH rows are already sent while first row is yielded. Close client; next iterator pull rejects rather than yielding buffered obsolete rows; new client recovers.                                                                                                                                                                                           |
| `late-callback`                              | Complete and retain old three-row FETCH; delay its application callback 120 ms. Invalidate its ephemeral token, close/reconnect and start a new token. Old callback is rejected by the harness fence; without that check it would still execute.                                                                                                                   |
| `header-default`, `header-literal-cap`       | Declare 1 MiB header; wait 60 ms before transmitting body. Defaults return the complete header. A 256 KiB literal cap closes after declaration, with **zero literal body bytes sent** in the TLS trial.                                                                                                                                                            |
| `multi-literal-cap`                          | One FETCH response announces two 200 KiB literals. Individual cap 256 KiB, response cap 300 KiB. First literal arrives; second declaration rejects before its body is sent. This bounds a response, not all responses in a command.                                                                                                                                |
| `mime-normal`, `mime-depth`, `mime-byte-cap` | Valid leaf wrapped in 8 or 30 multipart layers; normal structure is returned, excessive depth is logged/discarded and FETCH resolves empty, 1 KiB line cap rejects an oversized MIME parameter. Depth guard runs after line assembly.                                                                                                                              |
| `metadata-aggregate`                         | 16 FETCH rows, each with a 160 KiB header, individual/response caps enabled. All 2.5 MiB headers are returned by fetchAll; no 2 MiB command budget is enforced.                                                                                                                                                                                                    |
| `partial-base64`, `partial-qp`               | Fetch raw MIME part 1 at exact advancing offsets in 7-byte slices, with NOOP between each completed slice; split Base64 quanta and quoted-printable escapes/soft breaks. Keep existing dependency Decoder across slices; reconstructed bytes equal the independent source buffer and raw encoding oracle. Independent Base64 decoding of every slice is incorrect. |
| `partial-256k`                               | Larger Base64 part, 256 KiB slices with literal cap 256 KiB and response cap 300 KiB. Exact-byte oracle and decoded-content equality; useful boundary is one tagged FETCH, with NOOP between slices.                                                                                                                                                               |
| `partial-interrupted`                        | Disconnect during second slice after two of seven declared bytes; only first slice is accumulated and download remains incomplete. No cache is finalized.                                                                                                                                                                                                          |
| `partial-oversized`, `partial-wrong-offset`  | Deliberately ignore requested seven-byte maximum or send a seven-byte reply with origin 99 for a request at origin 0. Raw fetch returns oversized bytes, or accepts bytes without exposing mismatched origin in its map. These are compatibility/safety failures, not successful bounded retrieval.                                                                |
| `lock-multiple`, `lock-error`, `lock-cancel` | Queue a second INBOX lock; execute FETCH + NOOP under first, reject FETCH with tagged NO, or hang FETCH and close at 220 ms. Normal errors require finally-release; close clears holder and rejects waiter.                                                                                                                                                        |

All rows include start/end UTC and monotonic offsets, command/range strings, per-command server bytes and tagged-send timestamps, native/client/peer close events, operation settlement and error, peak sampled RSS/heap/external memory, event-loop delay, subsequent reuse or recovery, and row delivery times. Final TLS trials additionally record `client-tagged-response` events, correlated by command tag. A null tagged time means no completion was sent, not zero duration. Cleanup close after a successful operation is marked by `cleanupStartMs`; it must not be confused with cancellation. `Outcome` describes API promise settlement only: public `noop()` discards its internal false return and can resolve undefined after an IDLE/connection failure. Thus `idle-hang-done` and `done-disconnect` show resolved API calls despite no NOOP being sent; the failure is visible in library diagnostics and missing wire completion. Promise resolution is not success evidence.

Bytes received count decrypted protocol payload on connection 1 between operation start and settlement, including any intervening NOOP in content/lock scenarios. Command `bytesSent` is the peer's attempted write total; a tagged-send timestamp is a server write timestamp, not proof the client has consumed it. Raw events retain the later parsed-tag timestamp. Memory baselines are taken after connect/initial SELECT in final runs. Samples include server allocations and telemetry; they are not precise library-only peaks or a production RSS guarantee. Short cases below histogram resolution may have no usable event-loop sample. Source findings, not timing averages, establish internal whole-response buffering.

Its readings are **contaminated** by transparent ESET IMAP inspection: delayed/changed literal framing and injected commands. The [diagnostic trace](../../../experiments/imap-transport/plaintext-interference.json) shows `addedByEsetSecurity` tags and removal of partial ranges. The [initial run](../../../experiments/imap-transport/initial-plaintext.json) is retained, including failure traces. An early TLS attempt with missing certificate files failed setup (NOT RUN for transport). The retained [TLS fixture-debug run](../../../experiments/imap-transport/fixture-debug-tls.json) has one incorrect SELECT barrier: fixture namespace LIST incorrectly advertised INBOX as a prefix, so the command was `SELECT INBOX/Archive`; correcting its root LIST response made the intended reselect fault execute. ImapFlow was never modified to force success. The excessive-depth expectation was revised to record actual successful-empty behavior, which **fails the metadata safety gate**, rather than treating it as safe rejection.

This fixture is a controlled peer, not a complete IMAP server. It does not validate OAuth/login, capabilities beyond rev1+IDLE, unsolicited live mailbox races, STARTTLS, BINARY/ESEARCH interoperability, real provider resource costs, compression, SMTP or side effects. Oversized header payloads and some multi-literal rows are synthetic byte stressors, not an email semantics test. Out-of-range SEARCH, wrong-origin and ignored-partial tests deliberately violate normal server behavior. Multi-response SEARCH is an accumulation stressor, not a claim all providers emit that form.

Server and client share an event loop and process; memory includes both, loop stalls affect both, and backpressure kernel queues/TLS buffers may retain extra data beyond the parser's logical budget. No exact cap on total process memory is proven. The close evidence is Node's native socket event plus the remote fixture endpoint, not packet capture or a proof of how long an arbitrary remote server retains an authenticated session. Timers cannot execute during synchronous parsing/CPU suspension. Sampling can miss transient peaks; the event-loop histogram also missed much of the deliberate immediate stall before its first sample, while separately measured watchdog lateness was 130.77–131.22 ms. Three repeats show local repeatability, not a tail-latency distribution or 30-seed fairness validation.

Safe incremental decoding is available for **one live continuous Base64/quoted-printable decoder in this controlled test**. Its state is not serialized or resumed after process restart. Charset conversion, flowed text, arbitrary MIME encodings, BINARY response semantics, malformed encoding, persistent content cache finalization, epoch change during assembly and provider offset compatibility are NOT RUN. A digest-correct synthetic reconstruction does not validate production cache lifecycle.

Dovecot/fault-proxy, lease/DB fencing, transaction cancellation, production connection budgets, LIST/SELECT comprehensive byte caps, remote mutations and the 50,000 + 10 experiment are **NOT RUN**. Their absence is explicit; this task's scripted peer allowance does not pass the full production evidence gate.
