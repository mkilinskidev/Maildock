# Phase 1 implications for the proposed IMAP engine

Based on [RESULTS.md](RESULTS.md), the installed ImapFlow 2.0.6 source and controlled real-client TLS transport experiments. Architecture baseline: `7ccabcad5390439e9ce906d1e9a9c196ffa04912`. The [approved proposal](../../design/imap-sync-engine/SYNC_ENGINE_ARCHITECTURE.md) and its validation plan are unchanged.

**One bounded-operation execution model remains technically feasible, conditionally.** A short, fully completed command can return a reusable selected connection. A hung command can be terminated by closing that connection and selecting a new one. Those observations support one account owner and reconsideration at real command boundaries. They do not establish the complete count/byte/time/persistence contract required to implement the production engine.

## Confirmed assumptions, within the fixture boundary

| Architecture section / assumption                                | Phase 1 evidence                                                                                                                                                                                         |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §4: small numeric UID interval SEARCH rather than full inventory | Dense 128-UID and sparse large intervals completed independently. Cardinality follows actual compliant hits, not numerical width. SEARCH result collection itself is not streaming.                      |
| §§4–5: a reusable client can yield between complete commands     | Full FETCH exhaustion plus explicit lock release permits the next lock/operation; authentication need not be repeated after healthy completion.                                                          |
| §5: one socket time-shares IDLE and data operations              | Real DONE is sent before queued NOOP; a delayed tagged IDLE completion blocks the next wire command. Closing is necessary when DONE hangs.                                                               |
| §§4,7,10: abort/reconnect rather than promise-only timeout       | close settles hung SEARCH/FETCH/SELECT/DONE and terminates native/peer transport, including ongoing trickle. Fresh selected client performs later work. Old connection is not reusable after abort.      |
| §9: same-owner ephemeral turn token is necessary                 | Already returned rows survive client close in application memory. Delayed callback executes unless explicitly fenced. Harness token rejects it; buffered iterator pull after close rejects.              |
| §§4,9: missing FETCH cannot establish complete metadata coverage | Deliberately omitted UID resolves successfully with fewer rows. Excessive token nesting can likewise yield an empty successful FETCH. Exact searched/returned identity comparison must remain mandatory. |
| §4: BODY.PEEK raw part slices can be independent operations      | Correct seven-byte and 256 KiB slices yield after tagged completion; actual NOOP runs between slices; a continuous decoder reconstructs synthetic content without corruption.                            |

## Assumptions disproven as automatic library guarantees

These are failures of implied defaults or shortcuts, not silent edits to the proposal, which already labels transport bounds as hypotheses.

1. **A small returned batch releases the connection.** First FETCH row holds a next callback. A paused consumer blocks parsing of following rows/completion even if tagged OK has been sent. Returning the generator early releases backpressure but leaves the wire command active until tagged completion. Releasing a mailbox lock before that completion permits another cooperating caller to queue; it does not make the socket free. Use a complete bounded command as the unit, not a slice of an unbounded generator.
2. **UID interval is a local result limit.** The interval constrains a compliant server, but SEARCH accepts out-of-range replies, collects across multiple responses and exposes results only at completion. Validate identity range after success for correctness; that postcheck cannot undo prior allocation. Dynamic widening cannot rely on a parsed result count alone to guarantee K=128 during collection.
3. **256 KiB per metadata item / 2 MiB per operation are ImapFlow defaults.** Defaults are 1 GiB for a literal/line and 2 GiB for one response. Configurable limits are real and useful, but one header literal is fully buffered before yielding. The tested literal cap rejects its announcement early; application header-length checks happen too late. A per-response cap does not stop sixteen valid sub-cap FETCH responses from exceeding the operation aggregate.
4. **Socket timeout is the absolute operation deadline.** Complete untagged trickle replies and partial-literal bytes keep 100 ms inactivity alive past total duration. A single external deadline must cover DONE, selection, search/fetch and any remaining commit budget without resetting per command. Even that timer cannot execute while the event loop is blocked; the 50 ms timer was delayed by deliberate 180 ms CPU work.
5. **Parser size/depth violation always becomes an explicit operation error.** Oversized literal/line/response paths close, often surfacing `NoConnection` to the caller while the real cause is in the error/log event. Excessive nesting instead logs and drops the untagged row, allowing tagged success. Neither empty result nor successful tagged status alone is complete evidence.
6. **Closing a client revokes every callback.** It tears down transport/requests/parser/locks; it cannot revoke promises already resolved or data retained by the application. Invalidate the turn token before closing and before admitting new authoritative work. All publication must be mediated by that token and durable owner/epoch checks.
7. **Raw partial fetch validates the response range.** It returns an oversized literal if the server ignores the partial request, and the formatted body-parts map does not expose origin verification. The wrong-origin counterexample needs a decision: preserve/validate protocol origin in a narrow transport adapter, or explicitly accept a compliant-server trust boundary with documented incompatibility. Returned-length validation after receipt is useful but is not a parser byte bound.
8. **Mailbox lock enforces exclusive use of the entire connection.** The holder spans several commands; lock-free NOOP still works. getMailboxLock is a cooperative mailbox selection mutex. Account-wide admission and command ownership cannot be inferred from its existence.
9. **Every resolved API call proves remote success.** Public noop() discards its command handler's false result. After an IDLE failure it can resolve without NOOP ever reaching the wire. SEARCH can return false on transport failure, and FETCH can return incomplete rows after tagged OK. Define successful evidence per operation and retain diagnostics; do not use promise settlement alone as the success criterion.

## Required transport work before Phase 2

No adapter or production changes are implemented here. The next review should approve the smallest changes that enforce the chosen contract:

- Configure parser line/literal/response limits before opening a client, with framing headroom and distinct metadata/content profiles. A 256 KiB literal limit and equal response limit would reject a valid cap-sized literal because the response includes framing. Decide how to handle multiple allowed literals in one metadata response and compatibility with large SELECT/LIST/MIME tokens.
- Enforce **aggregate per-operation decoded wire/identity budgets before full library accumulation**, especially SEARCH and many FETCH rows. A public socket observer that closes on excess can bound accepted traffic approximately, but cannot prevent allocation of a current socket/TLS chunk or synchronous parsing already underway. Decide whether a decompressed transport gate and request-aware parser/result hook are required; validate their overshoot before claiming 2 MiB or K exactness. Do not merely add a Promise.race or slice the returned array.
- Choose a publication boundary requiring tagged completion, exact result identity/evidence checks, valid owner/epoch/turn and finally-release of mailbox ownership. Abort oversize/incomplete operations conservatively; never advance progress from a dropped row, partial SEARCH or false result. Preserve the error event that explains `NoConnection`.
- Require destructive timeout cancellation, observe settlement and native close, reject/clear queued work on the obsolete client, then create a fresh client. Physical remote session retirement through partitions is still separate from local release. Healthy close measurements do not set failover/grace periods.
- Decide how literal/MIME response origin is validated before accepting a content slice. Use continuous transfer decoding across slices; do not independently decode seven-byte Base64/quoted-printable chunks. Choose restart behavior: replay from a safe offset with decoder state reconstruction, or discard/restart an incomplete part. Decoder persistence is unverified. Ensure content remains unavailable until a final complete, epoch-valid assembly.
- State the absolute-time guarantee honestly. An event-loop timer can enforce network hangs under a responsive process. If an unconditional local maximum is required under synchronous parser stalls/process suspension, isolated parsing/worker termination or external supervision needs separate approval and evidence. Do not extrapolate the subsecond socket teardown into a provider SLA.

ImapFlow's configurable parser limits mean **a wholesale transport replacement is not justified** by this phase. A narrowly scoped adapter/instrumentation change is likely enough for ordinary compliant servers, but aggregate collection, origin visibility and depth/error completeness need explicit design decisions. Strict preallocation byte/K guarantees may require library-level hooks or a patch. None is silently added here.

## Remaining unverified architecture assumptions

| Topic                                                                          | Status / why Phase 1 cannot establish it                                                                                                                    |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §4 timing settings: healthy 2 s, total 10 s, commit 2 s                        | A real 10 s trickle abort was measured. Healthy local synthetic timing is not provider latency; DB time and event-loop CPU worst case are unverified.       |
| §5 global/account sockets, watcher eviction, C=1/2/5 limits                    | Single-client serialization is observed; shared quotas, external clients, account admission and partition overlap are NOT RUN.                              |
| §5/§9 coordinator lease/epoch and commit fencing                               | Per-turn harness token only. No PostgreSQL writer, lease takeover or commit uncertainty was exercised.                                                      |
| §§6–7 progressive descending windows, widening/shrink, arrivals during history | Small transport primitives only; no real sync algorithm, 50k inventory, scheduler or 50,000 + 10 trial.                                                     |
| §§8–10 membership/deletion/flag convergence                                    | Missing FETCH reinforces conservative evidence checks; full state-transition, equal-count churn, CONDSTORE and persistent-omission liveness remain NOT RUN. |
| §11 fairness/resource headroom                                                 | No receiving selector, multi-account worker load or DB admission is implemented.                                                                            |
| §12 preserved user integrations                                                | No application changes. Production OAuth/drafts/SMTP/commands/conversations/cache behavior not revalidated here.                                            |
| LIST/SELECT/MIME compatibility and real providers                              | Scripted rev1 peer only; Dovecot/fault proxy, provider tests, compression/BINARY/ESEARCH and adverse encoding/charset behavior remain NOT RUN.              |

Before Phase 2, review the failed/uncertain gates and approve any architecture amendments: the transport trust boundary, exact versus approximate aggregate memory limits, observable parser failure/completeness, content-origin validation, restartable decoding and event-loop deadline semantics. Keep the one-owner/common-selector model unless later evidence requires changing it. Close/network and publication fencing remain distinct responsibilities; a second engine or second data socket does not fix these shortcomings.

This phase ends with the harness, source evidence, measurements and reports. It does not authorize the 50,000 + 10 experiment or production implementation. Wait for review.
