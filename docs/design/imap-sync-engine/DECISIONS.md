# IMAP receiving decision log

2026-10-12 final architecture revision. **APPROVED** means the supplied user direction, **RECOMMENDED** means this review's technical choice awaiting acceptance, **OPEN** means a contract or compatibility/product decision remains unresolved. Stage 1 authorization, 2026-10-12: **D15 — APPROVED: Variant A, logical commit-time authority.** Physical WAL durability may occur after lease expiry when authorization at L was valid and serialized with takeover. Client-only pre-COMMIT checks and stale-owner commits remain prohibited. D07–D09 directions are approved for disabled, isolated Stage 1 implementation; their exact production mechanisms remain unproven. The retirement prerequisite investigation is recorded in [Stage 1 results](../../implementation/imap-sync-engine/STAGE_1_RESULTS.md).

Stage 1 validation, 2026-10-12: D07–D09 now have isolated implementation evidence for the revocable dedicated executor, database ordering and single-mailbox persistence API. Local retirement does not require synchronous backend disappearance; conflicting database locks serialize old COMMIT, takeover and recovery. D15 remains APPROVED Variant A. The accepted implementation uses fresh owned clients rather than reusing retired clients. See [Stage 1 results](../../implementation/imap-sync-engine/STAGE_1_RESULTS.md) for the retained counterexample, TLS teardown correction, real PostgreSQL gates and trust boundary. This validates the disabled component, not all future writers or a production release.

The Stage 1 authorization above accepts D07–D09 directions and D15 semantics within that scope. Recommendations D10–D14/D17–D18 still need review acceptance before their affected stages. D10/D16 need explicit contract/product choices. Optional later second lane/CONDSTORE/QRESYNC/parser isolation does not postpone required fallback correctness, ordinary input budgets or MIME/provider release gates. No subsequent stage or production cutover is authorized.
