# v1.0.1 hotfix design review

Baseline: latest fetched origin/test; clean working tree; dedicated fix/v1.0.1-imap-performance branch. Both investigation reports read and findings verified against installed ImapFlow 2.0.6 / pg-boss 12.33.7 and current source. No production access.

## Architecture and invariants

Delta worker owns a durable stately mailbox job and a PostgreSQL mailbox try-advisory lock. DeltaSyncService selects the epoch, loads a local placement UID snapshot, and persists new metadata/UID frontiers transactionally per batch. Epoch mismatch deletes obsolete placements and requests recent-window rebuilding. Empty recent bootstrap retains SINCE cutoff. CONDSTORE uses changedSince with SELECT's (not later STATUS's) MODSEQ; generic fallback fetches known flags. QRESYNC is reported as a capability but no VANISHED reconciliation exists. Every provider operation owns a guarded, read-only selected client with awaited teardown. Completion persists counts and MODSEQ only after reconciliation; retries revisit uncommitted work.

Content has a separate single-slot stately queue, four retries with jitter/backoff capped at 900 seconds and 900-second expiration. Pending persistence precedes enqueue; active and queued successor can coexist under stately. Provider streams selected text parts, verifies epoch, and then service sanitizes/persists ready content. UI polls pending/fetching but stops at failed. Ready rows already resist failure overwrites. OAuth refresh retains account row locking and rotation. Existing fixtures cover provider calls, service PostgreSQL persistence, pg-boss, OAuth, hostile HTML and reader rendering; Docker is available locally.

## Selected algorithm

Choose Strategy B: presence batches independent of metadata size, at most 1,000 UIDs and 8,000 UID-set characters. Explicit UID lists preserve generic IMAP behavior, bound response size to 1,000 UID integers, and avoid retrieving unindexed history. Largest unchanged 41,246-UID folder: 275 presence SEARCHs become 42 for short UIDs (up to 57 for maximum-width UIDs). Stage counters measure actual commands. Keep metadata/flag fetch batching unchanged. Validate successful response shape, UID bounds, duplicate and unsolicited UIDs; false/undefined/error is failure. Collect missing UIDs, then delete only after all presence commands and STATUS succeed and client health is verified. Bound deletion persistence into existing-size batches. No MODSEQ advancement on failure. Arrivals cannot delete UIDs outside the snapshot; expunges observed during a successful SEARCH are removed, later expunges converge next delta.

Strategy A (SEARCH ALL) rejected for this hotfix: no provider-side response-size bound, no independent completeness/count witness that remains valid during arrival/expunge, and unindexed historical mailbox size may greatly exceed local size. A server falsely returning valid partial SEARCH data with tagged OK cannot be detected by either existing or proposed bounded search; protocol compliance is required. Malformed, rejected and interrupted responses must fail closed without silent fallback.

## Reliability and diagnostics

Use monotonic, aggregate, allowlisted stage summaries with random correlation IDs; instrument service credentials/persistence, provider connect/select/search/flags/status/content stream/teardown, MIME selection and Google lock acquisition/token HTTP. Never emit raw provider text or payloads. Logging exceptions must not affect outcomes. Normalize timeout codes ahead of message heuristics; retain socket inactivity, connection setup, TLS/auth, disconnection and cancellation distinctions, including original asynchronous socket failures.

Content presentation consults durable queue state: created/retry/active means pending/fetching even if an attempt persisted failed. Only exhausted/cancelled/completed-without-cache is terminal. Manual scheduling serializes producers with a transaction advisory lock and suppresses any live job, preserving delayed retries. Missing jobs for pending/fetching are repaired on detail polling (bounded by polling interval while reader is open), never by elapsed attempt age. Existing durable jobs recover execution loss through pg-boss expiration. No infinite automatic rescheduling of terminal jobs. Guard state writes against a concurrent ready cache. No schema or HTML/image-policy changes.

## Fairness decision

Defer hard cross-account admission pending a separate durable design. Installed pg-boss groupConcurrency counts active groups using statement snapshots; source has no group-exclusive claim constraint for simultaneous fetches. Adding account IDs alone is not a proven cross-process exclusion guarantee, and existing ungrouped jobs need transition handling. Waiting account locks inside workers would still occupy both slots; repeated requeues consume retry budgets. Do not ship an unverified gate. Reduced reconciliation work mitigates occupancy without promising starvation prevention.

Fairness and closed-reader orphan maintenance remain explicit follow-ups.
