# Phase 1F: Microsoft OAuth2 mail authentication

Maildock uses MSAL Node's confidential-client authorization-code flow against the Microsoft identity platform `common` v2 authority. Configure `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET` on both web and worker processes. Register a **Web** redirect URI matching `${APP_ORIGIN}/api/oauth/microsoft/callback` exactly. The app registration must allow organizational accounts and personal Microsoft accounts to support both Microsoft 365 and Outlook.com. Add delegated Exchange Online permissions `IMAP.AccessAsUser.All` and `SMTP.Send`; consent and tenant policy must permit them. Maildock requests `openid`, `profile`, `email`, `offline_access`, and both full Outlook resource scopes. Do not register a SPA redirect URI or use a public-client flow.

The owner clicks **Connect Microsoft account**. Maildock creates a random, one-use, ten-minute state bound to the current instance session, stores only its SHA-256 digest, and encrypts the PKCE verifier. MSAL constructs the authorization URL and exchanges the callback code server-side. State is atomically consumed before any code exchange. Maildock creates an IMAP/SMTP account with `outlook.office365.com:993` (TLS) and `smtp.office365.com:587` (STARTTLS), then schedules existing mailbox discovery. Reconnect uses the same flow and requires the same Microsoft home account ID to avoid associating an existing mailbox read model with a different identity.

`mail_accounts.auth_method` selects password or OAuth2. Password accounts retain their encrypted IMAP/SMTP passwords and existing behavior. OAuth accounts have no stored mail password. The serialized MSAL user token cache, including any refresh-token material, is encrypted with the existing AES-GCM credential service and account-specific associated context. Access tokens exist only while a provider connection is prepared. No tokens, codes, cache material, or client secret are returned by account views or logged. Each silent acquisition locks the account row within a PostgreSQL transaction, reloads the encrypted cache, and persists MSAL cache changes before releasing the lock. That serializes worker refresh and preserves rotated refresh state across processes. When MSAL requires interaction, the account shows **Reconnect required** and the owner can reconnect.

The account service resolves a discriminated password or OAuth2 credential and passes it to the existing protocol adapter. ImapFlow receives `auth.accessToken` for XOAUTH2; Nodemailer receives OAuth2 `auth.accessToken`. The provider never encodes XOAUTH2 itself. A new access token is resolved on each worker job and each IDLE reconnect, so resumed work can silently refresh expired access. Active IMAP connections use their token only during login; subsequent reconnects resolve again. SMTP verification reports a sanitized message if SMTP AUTH is disabled by mailbox or tenant policy. Tenant consent restrictions and revoked authorization require administrator action or reconnect.

## Manual verification with a real Microsoft account

1. Create the Entra app registration with the Web redirect URI and supported account types above. Add the delegated Exchange Online permissions; grant consent as required by the tenant.
2. Put the client ID and secret in the web and worker environments, alongside the existing credential encryption key. Apply forward migration `0008` and restart both processes.
3. Connect a Microsoft 365 mailbox and, if permitted by the registration and account policy, an Outlook.com mailbox. Confirm discovery, recent sync, delta polling, and IDLE reconnect work after an access token expires. Confirm connection test reports IMAP and SMTP separately.
4. Revoke consent or invalidate the refresh state, confirm **Reconnect required**, then reconnect the same identity. If SMTP verification fails, check authenticated SMTP settings for the mailbox and tenant.

The automated tests use a deterministic MSAL client double and PostgreSQL to cover state, encrypted cache, rotation, revoked authorization, protocol option mapping, and worker credential resolution. They cannot replace a live tenant consent and protocol smoke test.
